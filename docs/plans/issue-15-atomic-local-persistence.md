# Issue #15 implementation plan

Source: https://github.com/jmn0space/gym-hud/issues/15
Base: main at 71e0524 (frontend shell from #14 merged).

## Goal and boundaries

Make every successful local action durable together with the synchronization work
needed to replay it. Reloaded UI must query IndexedDB, not reconstruct a queue or
active-session presence from memory. Implement the shared persistence foundation
and connect its recovery/error lifecycle to the existing shell. Full PAD controls,
backend sync, authentication and service-worker installation remain separate issues.

Dependency #13 is open. The user confirmed using its proposed local baseline of at most one ACTIVE
session per type (PAD, resistance, cardio), with simultaneous different types
allowed and one Resume card for each. Describe envelope and ordering choices as a
versioned **local contract**, pending backend agreement; do not claim #13 is closed.
The atomic local ordering required by #15 supersedes the contradictory diagrams in
the current spec. No server conflict, authentication or acknowledgement protocol is
invented here.

## Implementation sequence

1. **Local contract and IndexedDB repositories.** Introduce a storage module with
   injectable database name/factory/clock/UUID generator for deterministic tests.
   Use native IndexedDB, versioned non-destructive migrations and the documented
   workout, routine/exercise, reference, outbox and sync-metadata stores. Store UTC
   ISO timestamps and secure UUIDs (with getRandomValues fallback for HTTP LAN dev).
   Expose read methods, one atomic commit method, cache methods and explicit
   outbox/metadata methods. Keep raw IDB handles private outside schema tests.
2. **Atomic logical actions.** One readwrite transaction covers all affected
   records, the action receipt, persisted sequence, and a single outbox envelope
   containing ordered record changes. Resolve only on transaction completion.
   Preserve stable action IDs across retries and retain receipts after queue
   acknowledgement. Validate nonempty actions, preconditions and one active
   session per type inside the same transaction; rollback fully on any failure.
   Use tombstones for deletions, retaining identity and timestamps. Preserve parent
   dependency ordering and use transaction-allocated sequence, not wall clock, for
   local edit ordering. No network await inside an IDB transaction.
3. **Recovery and UI boundary.** Read a consistent startup snapshot of persisted
   domain data and pending outbox. Provide a React storage provider/hook with
   loading, ready, saving and error states; successful writes refresh the snapshot
   only after commit. Visibly report open/read/write errors with retry. Home uses
   persisted active sessions and derives PAD WALKING/PAUSED/RESTING state and elapsed
   time from stored intervals. Timers refresh display only. Keep current unavailable
   domain pages honest until their feature issues implement controls.
4. **Acceptance-focused tests.** Add fake-indexeddb to the locked dev dependencies.
   Test record/outbox atomicity, late transaction failure and rollback, reopen after
   commit, schema upgrade preserving pending actions, multi-record PAD finish/next
   bout examples, tombstones, parent ordering, monotonic sequence despite clock
   rollback, duplicate action IDs even after acknowledgement, concurrent starts
   through independent connections, cache/metadata persistence, and UI success only
   after commit with recoverable failures. Use fresh DBs per test and StrictMode.
5. **Integration and review.** Run locked install, typecheck, lint, all frontend
   tests, production build and existing dependency audits. Inspect the final diff
   and exercise a real browser reload/error path if browser tooling is available.
   Document exact automated results and a manual Android checklist; do not label
   real-device/process-termination testing as done without running it.

## Shared module interface (agents must coordinate any necessary changes)

`frontend/src/storage/index.ts` exports:

- `createLocalRepository(options?)` -> `LocalRepository`; lazy open; `close()`.
- `createUuid()` and `utcNow()` helpers.
- `DomainStore`: walking_sessions, walking_bouts, walking_pauses, walking_rests,
  resistance_sessions, resistance_rows, cardio_sessions, routine_templates,
  routine_exercises, exercise_registry.
- `LocalRecord`: UUID `id`, other JSON-compatible fields; persisted records have
  `created_at`, `updated_at`, `deleted_at: string | null`.
- `LocalAction`: `{ actionId: string, changes: DomainChange[], preconditions?:
  RecordPrecondition[] }`.
- `DomainChange`: `{ store, operation: "put", record }` or
  `{ store, operation: "delete", id }`; put is a full record replacement preserving
  original creation time; mutation metadata is generated by the repository.
- `RecordPrecondition`: `{ store, id, expected: Record<string, JsonValue> | null }`;
  null requires absence, otherwise selected persisted fields must match.
- `CommitReceipt`: `{ actionId, sequence, committedAt }`.
- `OutboxEntry`: `{ version: 1, mutation_id, sequence, created_at, changes }`;
  immutable captured payloads with explicit operation/entity identity, parent
  creates before children and child deletes before parents.
- `RecoverySnapshot`: `{ records: Record<DomainStore, LocalRecord[]>,
  pendingOutbox: OutboxEntry[] }` (live domain records only, ordered pending queue).
- `LocalRepository`: `commitAction(action)`, `readSnapshot()`,
  `getRecord(store,id,includeDeleted?)`, `listRecords(store,includeDeleted?)`,
  `listPendingOutbox()`, `acknowledgeOutbox(mutationId)`,
  `getSyncMetadata(key)`, `setSyncMetadata(key,value)`,
  `readReferenceCache(key)`, `writeReferenceCache(key,value)`, `close()`.
- options: `{ databaseName?, indexedDB?: IDBFactory, now?: () => Date,
  uuid?: () => string }`; default DB name `gym-hud-local`.

References are cached separately from mutable workout snapshots. Internal sequence,
client identity and action-receipt metadata must be isolated from caller metadata.
Read APIs and UI must not silently substitute empty data when IndexedDB fails.
A read failure after a successful commit must not falsely claim the write rolled back.
